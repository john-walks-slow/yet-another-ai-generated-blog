## 1. 设计 Brief（从项目基因推导）

这个博客的基因，决定了它的设计不能是「又一个好看的模板」：

| 基因 | 设计含义 |
| --- | --- |
| 站名自嘲（「又是一个」），内核极个人 | 设计本身必须**极度认真**，才能托住内容姿态的松垮——「认真对待不认真」 |
| 内容全部 AI 生成，人只出点子与审读 | 「谁写的」可以成为**可见的、诚实的**设计元素，而不是需要遮掩的事实 |
| 主题：技术 / AI / 哲学 | 排印应偏**刊物感、思想感**，而非产品营销感 |
| 中文为主，中英混排 | CJK 排印质量是硬指标，不是事后补丁 |
| 每周两更、人力刻意压到最低 | 所有设计必须兼容「零装饰的列表页 + 自动生成的文章页」，不允许出现需要人手工维护的视觉元素 |
| 反 AI 均质感 | 必须与 AI 生成网站的视觉默认值（紫蓝渐变、玻璃卡片、emoji 列表）拉开明确距离 |

**一句话设计目标**：一个看起来像「被机器认真排过版的印刷品」的网站——它对排印的讲究程度，与它对署名独创性的不在乎程度，恰好成正比。

## 2. 调研结论摘要（设计依据）

完整论证见两份调研报告，此处只列被本方案采纳的结论：

1. **主线范本：Works in Progress**（worksinprogress.co）——「极简但极具设计感」的当代最优解。核心手法：**等宽字体做界面/元数据层 + 衬线做正文层、纸感底色替代纯白、单一强调色（链接色即品牌色）、全局零圆角**。它同时是对「AI 生成网站均质感」的天然抵抗。
2. **气质范本：gwern.net**——「认真的学究气」：侧栏注、首字下沉、克制的古典点缀。其设计原则「视觉差异必须是语义差异」「装饰须先挣得」直接采纳为本项目设计公理。
3. **差异层（无人占据的空位）**：调研未发现任何博客同时做「WiP 式认真排印 + AI 生成自反元数据」。站名《又是一个ai生成的博客》天生站在这里——这是模板的核心差异点。
4. **CJK 基线**：正文宋体、界面黑体/等宽、行长 30–45 字、行高 1.8–2.0、盘古之白（构建期 AutoCorrect + CSS `text-autospace` 双保险）、慎用 justify。
5. **反面清单**：slopfair 总结的 AI 设计陈词滥调（紫渐变英雄区、玻璃卡片、emoji 列表、不敢用零圆角）全部列入禁用清单，作为发布前 QA 门禁。
6. **技术结论**：Astro 6 纯静态 + 官方 blog 模板起步自研主题 + Cloudflare（Workers 静态资产，2026 新项目默认路线）。字体走构建期子集化（cn-font-split），单字重子集 30–80KB。

**被否决的方向**（及理由）：
- 产品级极简（Linear/leerob 风）：与 AI slop 视觉默认值距离太近；
- 全站粗野主义/玩梗：反讽会疲劳，主线必须是「可以安静阅读两百次的排印」；
- 手绘插画风：与「人力投入刻意最低」的基因冲突；
- gwern 式全灰阶：学究气足，但中文语境下「纸 + 墨 + 朱砂」比纯灰阶更有刊物气质——灰阶作为暗色模式的参考。

## 3. 设计概念：「机器排版，人签名」

模板的一切视觉决定都从同一个概念推导：

> **机器负责排版，人只负责签名。**
> 每一个视觉差异都是语义差异（gwern 公理）：在这个站上，你能从字体和颜色直接看出「这一块是谁的」。

由此定义**三层视觉语义系统**——这是整个模板的签名，也是它区别于一切现成博客模板的地方：

| 层 | 谁的声音 | 视觉载体 | 用在哪里 |
| --- | --- | --- | --- |
| **机器层** | 生成它的机器 | 等宽字体（JetBrains Mono + 黑体 fallback）、小字号、大写拉丁标签 | 导航、日期、标签、阅读时长、生成记录、构建信息、归档账本 |
| **阅读层** | 被排版的文本 | 宋体（Noto Serif SC + Source Serif 4 西文）、大字号 | 站名、文章标题、正文 |
| **人的痕迹** | 那个只出点子和阅读的人 | ① 黄色荧光笔划线 ② 楷体（霞鹜文楷）引语 ③ 朱砂「已阅」章 | 作者划的重点句、题词/作者按、文末鉴藏印 |

配套色彩语义：

- **靛蓝 = 人的路径**（链接，全站唯一的「功能色」即品牌色）
- **黄色 = 人的指纹**（荧光笔，只出现在正文里人划过的地方）
- **朱砂 = 人的签名**（已阅章，每篇文章出现且仅出现一次）

这套系统的反讽张力是自动生效的：**站上最醒目的「人的痕迹」，恰恰是「人几乎没干什么」的证据**——荧光笔旁边写着「人工投入 12 分钟」，已阅章盖在「未经人工润色」的声明之下。不需要任何玩梗文案，设计自己会讲话。

设计同时为「梗的时效」留了后路：当 AI 生成成为默认、自嘲不再新鲜，本站耐久的差异将是**账本与排印**（诚实元数据 + 印刷工艺）——设计系统的重心无需重构即可完成迁移。

## 4. 设计系统规范（Design Tokens）

### 4.1 色彩（浅色「纸」模式为唯一 v1 主题）

```
--paper:      #FAF7F2   纸白（暖，非纯白）
--ink:        #1A1815   墨（近黑，暖）
--ink-soft:   #6F6A61   次级文字（暖灰）
--ink-faint:  #A39D92   弱文字（页脚、构建信息）
--hairline:   #E4DED3   发丝线（分隔线、边框）
--indigo:     #363B8F   靛蓝——链接与交互（源自 WiP 实测 token）
--highlight:  #F4D06F   荧光黄——人的划线（源自 WiP 实测 token）
--seal:       #B3423A   朱砂——已阅章
```

规则：
- 彩色只有三个：靛蓝、荧光黄、朱砂，各自绑定语义，**不得挪用**；
- `::selection` 用荧光黄——有意的「第四种声音」：把同一支荧光笔交给读者，版权页声明这一点；
- 背景永远不用纯白 `#FFF`，墨色永远不用纯黑 `#000`（印刷感的关键）；
- 全局 `border-radius: 0`（锐利印刷感，反 AI 默认圆角）；
- 无阴影、无渐变（唯一例外：荧光笔的黄色平涂底）。

深色模式：**v1 不做**（呼应纸本概念，避免宋体深色渲染发糊的工程负担），v2 以「墨 mode」形式加入（纸黑 #171512 底 + 灰阶参考 gwern）。这是一个明确的取舍决定，见 §10 开放决策点。

### 4.2 字体（三层语音 → 三套字族）

```
/* 阅读层：宋体正文（西文/数字走 Source Serif 4） */
--font-serif: "Source Serif 4", "Noto Serif SC", "Source Han Serif SC",
              "Songti SC", "SimSun", serif;

/* 机器层：等宽（中文落在黑体上） */
--font-mono: "JetBrains Mono", "IBM Plex Mono", ui-monospace,
             "Noto Sans SC", "PingFang SC", "Microsoft YaHei", monospace;

/* 人的痕迹：楷体（仅引语/题词） */
--font-kai: "LXGW WenKai", "Kaiti SC", "KaiTi", "STKaiti", serif;
```

工程方案（依据技术调研 §5）：
- Noto Serif SC（400/700/900）+ Source Serif 4（拉丁/数字，Astro 6 内置 Fonts API 自托管）+ 霞鹜文楷（仅引语，字面小）全部**构建期子集化**，单字重子集 30–80KB；
- **P0 先用 pyftsubset 做「全站字符集单文件子集」（一次性脚本），P2 升级为 cn-font-split 分片方案**——宋体阅读层是设计本体，不允许在交付版本里缺席；
- 等宽层西文用 JetBrains Mono 自托管（体积小、字重全），中文回退系统黑体；
- CI 加「子集字符集 ⊇ 全站字符集」校验，防止新文章出现子集外字符静默回退；
- `font-display: swap`（正文 400）/ `optional`（700/900 小用量字重，杜绝排版跳动）；不对分片字体 preload；
- 用 `ascent-override / descent-override` 校准回退字体度量防 CLS；分片字体「逐片到达、逐次重排」的重排在 P2 分片方案时一并处理。

**站名大小写是设计决定**：站名中的「ai」恒为小写（沿用站长原话的松弛感——masthead「又是一个ai生成的博客」、英文副标 yet another ai-generated blog 全小写）；行文提及 AI 时正常大写。

### 4.3 字号与版式基线

| 元素 | 规格 |
| --- | --- |
| 站名大字（首页） | 宋体 900，clamp(2.25rem, 7vw, 4.25rem)，行高 1.2 |
| 文章标题 | 宋体 900，clamp(1.625rem, 4vw, 2.5rem)，行高 1.3 |
| 导语 standfirst | 宋体 400，1.125rem，`--ink-soft` |
| 正文 | 宋体 400，**17px / 1.9**，列宽 **36em**（约 32–38 字/行） |
| 机器层文字 | 等宽 0.75–0.8125rem，letter-spacing 0.02em，拉丁标签全大写 |
| 段间距 | 1.25em（不用首行缩进） |
| 对齐 | `justify` + `text-justify: inter-character`（标准值；Chrome 不解析 text-justify，其默认 CJK 断行已接近两端对齐。QA 时若中英混排拉伸难看，回退 left——已列为验收检查项） |
| 中英混排 | 构建期 AutoCorrect + CSS `text-autospace: normal` 双保险 |
| 间距网格 | 4px 基准（4/8/12/16/24/32/48/64/96） |
| 留白立场 | 刊物级奢侈留白——「密度即诚实」的路线让给归档页，阅读页必须疏朗 |

### 4.4 动效（克制立场）

- 全站**一个**签名动效：链接 hover 时靛蓝色从文字底部 1px 发丝线「生长」为下划线（120ms, ease-out）；
- 焦点态：`:focus-visible` 用靛蓝 1px outline + 3px offset（默认 outline 与印刷美学冲突，但不牺牲键盘可访问性）；
- `prefers-reduced-motion: full disable`；
- 无滚动入场动画、无渐显、无 parallax——「零动效也是立场」（rauchg/DF 路线），唯一的运动留给链接，因为它是「人的路径」。

```

要点：
- 元数据在标题**上方**（WiP 顺序）：先机器层、后阅读层——「机器先到，文本后到」；
- **生成记录（Generation Record）**：本站签名组件，等宽账本格式，数据来自 frontmatter，AI 生成流程必须填写；
- **「已阅」章**：34px 朱砂方章、**阳文**（朱底、纸色「阅」字）、-6° 微倾——人的鉴藏印，每篇一枚。它把这个博客的人类角色定义为「藏书家」：不写，但读，并盖章；
- 侧栏注：桌面端进右缘栏（Tufte/gwern 式），窄屏折叠为行内 `<details>`；
- 首字下沉：所有文章页统一启用（宋体、3 行高）——「先极简、后点缀」的装饰授权论：全局克制，才配得上这一处古典。

### 5.3 归档页（/archive）

- 等宽账本：年份分组、`日期 · 标题 · 标签 · 字数` 表格化排布，行高紧凑、发丝线分隔；
- 「密度即诚实」在此页释放——它看起来像一个数据库导出，这正是机器层的本相；
- 页首一行等宽统计：`TOTAL 14 POSTS · 41,230 字 · 人工累计 3.2 小时`。

### 5.4 关于页（/about）

- 宣言页：为什么做这个站（认真对待不认真 / 放下独创性与品质担保的面子和负担）；
- 文案素材建议直接取用站长本人的表述（需确认，见开放决策点），排印上给予最高规格：楷体题词 + 首字下沉 + 大留白；
- 结构：一段宣言 + 「这个博客如何运作」的流程说明（点子 → 生成 → 门禁 → 已阅 → 发布）+ 人工投入哲学。

### 5.5 版权页（/colophon）

站点成分表——设计谱系的诚实交代（WiP 页脚「Designed by And–Now」的传统）：

```

## 6. 内容模型（frontmatter schema）

```yaml
title: string            # 必填
date: ISO-8601           # 必填
summary: string          # 必填，一句话，首页列表与 RSS 用
tags: string[]           # 必填，≤ 3 个
model: string            # 必填，如 claude-opus-4.6 / deepseek-v4
human_minutes: number    # 必填，人工投入总分钟数（选题+审读）
ideation_minutes: number # 可选，选题分钟数（供生成记录展示拆分）
review_minutes: number   # 可选，审读分钟数
revisions: number        # 必填，修订轮次
human_polish: boolean    # 默认 false，是否人工润色
prompt_url: string       # 可选，生成过程/大纲链接
draft: boolean           # 默认 false
```

- 用 Astro Content Layer + Zod 强校验：缺字段直接构建失败——这是 AI 内容流水线的第一道质量闸门（技术调研 §7.3）；
- `human_minutes` 等字段是设计系统的数据源：生成记录、首页计数、归档统计、页脚累计全部由它构建期汇总；
- 未来全自动流水线（PR 门禁 → cron 自动发布）在模板之外作为独立 feature 实施，本模板为其预留 schema。

## 7. 技术方案

```
yet-another-ai-generated-blog/
├── astro.config.mjs          # site URL、markdown 配置（remark 插件链）
├── src/
│   ├── content.config.ts     # Zod schema（§6）
│   ├── content/posts/*.md
│   ├── styles/tokens.css     # §4 design tokens
│   ├── styles/global.css     # 排印基线 + prose 样式
│   ├── layouts/Base.astro    # <head>、页脚、构建信息
│   ├── layouts/Post.astro    # 文章版式（侧栏注 grid）
│   └── components/
│       ├── Masthead.astro    # 等宽导航
│       ├── PostList.astro    # 年份分组列表
│       ├── GenerationRecord.astro  # 生成记录账本 + 已阅章
│       ├── Sidenote.astro / remark-margin-note
│       ├── Highlight.astro / remark-highlight   # ==荧光笔==
│       └── Colophon.astro
├── scripts/fonts.mjs         # cn-font-split 子集化 + 字符集校验
└── public/fonts/             # 子集 woff2（构建期生成）
```

- **Astro 6 纯静态、零客户端 JS**：侧栏注用 CSS grid + `<details>`，回到顶部用 `<a href="#top">` 锚点。唯一例外（统计脚本）推迟至 P3 并须在版权页声明；v1 不注入任何第三方 JS；
- **纯 CSS + custom properties**，不引入 Tailwind——设计 token 驱动的印刷美学用原生 CSS 更干净，也远离 AI 生成代码的框架默认值；
- **remark 插件链**：`remark-pen`（`==…==` 荧光笔，自研，避免与 npm 已有 remark-highlight 撞名）→ margin-note（`^[注]` 上标转侧栏注）→ AutoCorrect（盘古之白/标点规范化，`autocorrect-node` 已验证可集成）→ reading-time（**中文口径 400–500 字/分钟**，按字符统计而非分词）；
- **RSS 全文输出**，item 内嵌「生成记录」HTML 块——站外阅读不丢站点签名；sitemap；`ai_generated: true` 元标记（合规最佳实践，技术调研 §8）；
- **基础 meta（P0）**：og:title/description/type/canonical + JSON-LD BlogPosting（把 AI 生成声明写进结构化数据）+ favicon（朱砂 ◈ 章图形——浏览器标签页是比首屏更高频的品牌触点）；
- **打印样式表（P1）**：`@media print` 隐藏导航/页脚、正文衬线直出——以印刷品自居的站点，应当经得起真的打印；
- **OG 图**（P2）：构建期模板化生成——纸白底 + 宋体标题 + 荧光黄划线 + 等宽元数据条，即「把本站版式压缩成一张卡」，无渐变无插画；
- **部署**：Cloudflare Workers 静态资产（2026 年新项目默认路线，静态请求免费不限量；纯静态产物与 Pages 随时可互迁）+ 自定义域名（免备案，硬成本仅域名 ~¥60–80/年）；
- **性能预算**：单页总传输 < 300KB（含字体子集），Lighthouse 移动端 Performance/A11y ≥ 95。

## 9. 验收标准（QA 门禁）

**反 AI-slop 清单**（任何页面发布前自查，源自设计调研 §6.7）：
- [ ] 无紫→蓝渐变、无玻璃拟态、无阴影卡片堆
- [ ] 无 emoji 列表、无「不只是 X，更是 Y」式文案
- [ ] 圆角全局为 0；间距遵循 4px 网格而非「到处 16px」的均质感
- [ ] 界面字体非模型默认输出那几款，且机器层/阅读层有明确字体对比
- [ ] 每页至少一处「只有这个站才有」的元素

**CJK 排印检查**：
- [ ] 正文每行 30–45 字；行高 1.8–2.0；中文与西文/数字间有盘古之白
- [ ] 子集字符集 ⊇ 全站字符集（CI 校验），无 tofu、无静默回退
- [ ] justify 在中英混排极端案例下不产生难看的字距拉伸（否则回退 left）

**签名测试**（差异化验收）：
- [ ] 双层字体语义系统（等宽=机器 / 宋体=文本 / 楷体+荧光+朱砂=人）全站一致
- [ ] 生成记录账本 + 已阅章 + 累计人工投入计数三件套就位
- [ ] 一个从未见过本站的人，10 秒内能说出「这个站的特别之处」

**工程验收**：Lighthouse 移动端 Performance/A11y/SEO ≥ 95；单页 < 300KB；`prefers-reduced-motion` 生效；无客户端 JS 依赖（JS 禁用时全功能可读）。
